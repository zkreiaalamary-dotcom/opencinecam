# Research roadmap

Start with the fastest controls that can change an implementation decision. Use a lab build, one handset, a fixed mount and an asymmetric chart with an independently timed moving marker. Fix camera route, lighting, exposure/antibanding, stabilization, destination and battery conditions across comparisons. Log actual metadata, surface topology and format, wall temperature category, firmware comparison token and build Git/APK hashes. Run each pair A/B then B/A after cooling; save suspect output privately and publish only derived metrics and digests.

## X-00 · Exact graph and failure receipts

Give the research adapter an explicit graph intent and negotiated receipt. Include descriptor-rejection reasons for camera raster, stream duration and codec capability separately. For each output, capture role, requested dimensions/format/usage and consumer construction, actual buffer dimensions/usage/dataspace when observable, logical/physical IDs, session type, template, crop/zoom/stabilization, and submitted/read-back AE and frame duration. Record the encoder's exact input format, chosen component and each lifecycle transition through final file retirement. Use stable failures such as `UNADMITTED_TUPLE`, `SOURCE_GEOMETRY_MISMATCH`, `CODEC_CONFIGURE_REJECTED`, `EGL_BIND_REJECTED` and `CODEC_FALLBACK`. Add structured first-divergence evidence and MediaCodec diagnostic, error code and transient/recoverable flags when available. Retain separate per-stage receipts without inferring unobservable source properties.

**Acceptance.** Unit-test synthetic `007`, `008`, `011` and `012` journal replays. Make idle success describe the actual admitted graph. A fallback outputs `HEVC intent → AVC file` as two records. A standalone direct HEVC path can lack GPU callbacks and still qualify from its matching sensor, encoded and file stages. Keep production descriptor policy unchanged until a tested route earns admission.

## X-01 · Carry over the UHD60 positive control

1. Reuse the Pura positive control conditions first: logical 0/physical 2, 3840×2160, [60,60], MediaRecorder HEVC, requested 60 Mb/s, encoder Surface only, no separate camera preview output. Keep the direct session entirely in the research adapter. Run the matched second-surface condition at 1280×720. Compare PTS, unique moving marker samples, sensor/buffer losses, actual payload bitrate, and chart geometry.
2. Try initial fixed AE range in session parameters as a separate comparison where admitted, preserving the identical repeating request. Current regular GPU route supplies initial AE range only in its RAW-plan branch. Report whether the key is listed as a session parameter and whether the request is accepted/read back. Treat this as a test variable for Huawei, even though the workaround already exists for other vendors.
3. If direct and second-surface cases split, test smaller preview sizes and a single-output GPU graph with exact UHD texture admission restricted to the lab. Use an independent configuration and topology receipt. Verify actual producer dimensions and instrument scaling. Use the encoder-only path for field recording if it wins, with a visible viewfinder limitation, or a verified low-rate monitor route if available.

**Acceptance.** Use a 4–8 s check, then at least 30 s and 120 s warm in `X-04`. At 60/1.001 target, proposed gate is average within 0.5%, zero repeated PTS, and zero unexplained intervals >1.5 frame periods in the stable window. Report maximum and p95/p99 intervals plus unique cadence via motion marker. Keep a correct high-quality UHD24/25/30 mode as a separate option.

## X-02 · Recover the exact codec contract

Use a deterministic EGL synthetic producer with phone camera closed. Reproduce the archived positive HEVC format at 1080p30 and UHD30 before reproducing the current failing format. Test Main8 then Main10 and one codec component per record. Compare omitted versus explicit suitable HEVC level first. Use the Pura explicit configuration as the positive seed: HEVC MainTierLevel51, Surface, Rec.709 limited SDR, frame rate, bitrate and 1 s GOP. Reconcile bitrate with selected tier/level and hardware caps for each test. Then add VBR, SAR and intended signal keys one at a time. Advance through `create → configure → createInputSurface → EGL window → start → first sample → stop → independent SPS/decode`. Verify actual output format. Apply only a deterministic per-build recipe once it passes; include bitrate range, alignment, policy/environment and exact graph in the capability key. Repeat 60 and 120 only after lower-rate controls.

**Acceptance.** Reproduce a success and a refusal with a single changed input or identify the first misbehaving surface/lifecycle stage. An encoder-only success qualifies the encoder contract and leaves camera compatibility pending. Catalog the short HEVC Main MediaRecorder route independently. Give graceful AVC fallback explicit provenance.

## X-03 · Repair Main10 geometry before Log

Use a target with four labelled quadrants, diagonal fiducials and gradients. Start at UHD30 from `E-PURA-5698009` and alternate four routes where they can be admitted: synthetic EGL RGBA1010102→HEVC Main10, direct camera→Main10, camera→GPU→Main10, and known-good AVC or HEVC Main8. Capture target coordinates before encoding where feasible. Verify `hvcC`, SPS coded/cropped dimensions, chroma format, display matrix and SAR; decode native YUV planes in FFmpeg and compare with second decoder/NLE. Compare correlation and MAD of halves and against shifted quarters in coded and oriented coordinates, border/fiducial positions, clipping and chroma phase. Use the Pura repeated-half records as positive controls and current OpenCineCam AVC as a negative control.

**Acceptance.** Correct full-frame fiducials and geometry through both decoders over repeated takes. If synthetic pixels are clean but camera direct repeats, prioritize camera/ISP surface-layout isolation and try fixed-consumer (ImageReader or EGL) comparisons scoped to public formats. If synthetic 10-bit repeats too, prioritize codec surface import/layout and EGL config. Escalate format pairing only after the source-side measurement can localize the first defective stage.

## X-04 · Qualify timing, audio and stability

For the 1080p60 excursion, run same-duration preview-only, GPU AVC and direct AVC with bright fixed light and randomized order. Record every frame timestamp, actual target buffer identity, frame number, interval and camera/GL/codec queue latency. Change stabilization and AE/flicker policy only in subsequent pairs. For UHD, apply the `X-01` gate to repeated warm runs and distinguish render resets, buffer losses, timestamp shifts and content duplicates. Reuse the project's capture diagnostics/cadence guard. Use a moving timing marker or coded LED and an audio impulse for clock checks where audio is enabled. Migrate timing in one explicit monotonic media epoch, preserve sensor presentation intervals and verify A/V start and drift. Calibrate the acceptance window with a known-good direct control.

## X-05 · Make useful grading latitude measurable

Develop a stable UHD24/25/30 SDR foundation with repeatable exposure, well-characterized 8-bit signal, optional verified high-bitrate codecs and separate monitoring from capture. Use exposure brackets plus grey/colour/highlight charts to estimate tone response, clipping, skin/neutral error, noise and detail per lens. Compare standard ISP, an experimentally accepted Camera2 tone curve and matched GPU-only transform. Camera2 tone-map readback under FAST is insufficient for an inverse ISP claim. A post-ISP flat transform can improve workflow consistency; an inverse transfer cannot recover clipped or previously quantized data. Measure 8-bit banding before shipping any flat option. A clean Main10 signal sourced from SDR can preserve downstream transform math, subject to `X-03`; label its provenance.

**Acceptance.** Show repeatable benefit against baseline in real chart exposure stops or grading errors, plus an independently decoded NLE round-trip. Reuse OCLog2 shader/numeric tests, sidecar, view assist and Resolve/OCIO/DCTL tooling, with versioned curve/gamut/range, provenance, measured clipping and shader hash. Use OCLog2 with HLG input only when a camera source is verified. Keep well-exposed standard SDR available alongside the grade-oriented option.

## X-06, X-07 and X-08 · Branch only when prerequisites hold

- **RAW16, `X-06`.** Repeat the already observed YUV+RAW_SENSOR session only to validate row/pixel stride, endian/bit alignment, dark/flat/clipping ramps, Bayer order and exact result-image pairing. Bound memory and disk. Compare single still and continuous short bursts; calculate bytes/s and sustainable buffer/window limits before considering a native RAW writer. Reuse existing RAW journaling and the host pipeline contracts if data is demonstrably valid. The fact that RAW_SENSOR bytes exceeded advertised white level requires unpacking/calibration, not a precision promotion. Earlier P010 configuration rejection supplies a control; new P010 trials need a new concrete graph or firmware reason.
- **HFR, `X-07`.** First constrained 1080p120 direct AVC with motion marker, then matching GPU passthrough and Main10/OCLog2 only when `X-02` and `X-03` pass. Report sensor, delivered and file counts across equivalent time windows. Treat 240 as a later separate graph. For OCLog2 HFR the upstream source remains SDR ISP until measured otherwise.
- **Regional stock, `X-08`.** Same chart and exposure on global SDR, global HDR mode if available, China SDR and China video Log. Capture UI mode and firmware provenance. Independently read VUI, SEI, dynamic range/transfer and source quantization. A stock HDR recording can motivate a documented OEM interface investigation. Treat any vendor key availability as a capability query, with no OS modifications.

## Make the lab spend attempts on decisions

Reserve baseline/control slots and a quota for each unresolved branch. Rank candidates by expected discrimination of a named hypothesis, product value, evidentiary quality, execution time and heat. Track a frontier across all resolved and unresolved cases with reason codes. Repeat an inconclusive high-value pair once before spending on nearby raster/FPS permutations. Skip unsupported paths with evidence and log every gate, including per-surface minimum/stall durations and camera/codec capability intersection. Audit `isFormatSupported` or equivalent advertisement separately from runtime trials.

Persist a compact manifest and streaming summaries with window length, ring overflow, dropped observation callbacks, and first/last timestamps per stage. Journal both exact-graph and failure receipts, then deduplicate artifacts by digest. A finalization receipt should cover muxer retirement and a decodable file. Promote only the exact graph/firmware/codec/format key whose color signaling, geometry, timing, source provenance and sustained duration meet that profile's stated thresholds.
